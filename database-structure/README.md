# 数据库的结构

**从底层原理理解数据库。**

《数据库的结构》是一个长期数据库技术研究与写作系列。

本系列不以介绍 SQL 语法或数据库日常操作为主要目标，而是试图回答一个更根本的问题：数据库内部究竟是如何工作的？为什么要采用今天这样的设计？

我们将从一条 SQL 的执行过程出发，逐步深入数据存储、索引、查询优化、事务与并发控制、日志恢复以及分布式架构，理解现代数据库背后的数据结构、算法、操作系统机制与工程取舍。

系列以 **PostgreSQL 为主要实验平台**，结合 Oracle、MySQL 的实现差异进行分析。每篇文章尽量从实际问题切入，通过原理解释、可复现实验和工程经验，让复杂的数据库机制变得容易理解。

这既是一套数据库技术文章，也是一项持续的技术研究和学习计划。

## 二、技术路线

本系列以通用数据库原理为主线，不局限于某一种数据库产品。

**主要实验平台：PostgreSQL**

重点研究：

- SQL 解析、查询重写与优化器
- Heap、Page、Tuple 等存储结构
- Shared Buffers 与缓存管理
- B-Tree、GIN、GiST、BRIN 等索引
- MVCC、事务快照与可见性判断
- VACUUM、Autovacuum 与空间回收
- WAL、Checkpoint 与崩溃恢复
- 物理复制、逻辑复制与高可用
- PostgreSQL 源码与内部实现

**比较研究：Oracle、MySQL InnoDB**

对于同一个数据库问题，尽可能分析不同系统采用的设计方案及其原因。比较的重点不是简单判断谁更先进，而是理解不同架构的适用条件与工程取舍。

## 三、文章的基本结构

每篇文章原则上包含六个环节，但正式写作以自然段落为主，不机械套用固定模板。

1. **提出问题**：从真实数据库现象或工程困惑切入。
2. **解释原理**：分析底层数据结构、算法与设计取舍。
3. **构造实验**：提供环境、建表语句、测试数据和完整代码。
4. **观察结果**：展示真实 SQL 输出、执行计划或系统指标。
5. **深入分析**：解释实验现象及其适用条件和局限。
6. **工程启示**：联系实际 DBA 工作与相关技术问题。

对于历史、架构思想等无法直接通过 SQL 验证的主题，可采用最小代码模拟、源码研究、官方文档或案例分析，并明确说明证据性质。

## 四、实验与发布原则

**所有涉及实验验证的文章，必须经过实际运行和技术审查后才能正式发布。**

实验记录尽可能包含：

- PostgreSQL 版本、操作系统及关键配置
- 完整的 SQL、测试数据生成方式及执行顺序
- 实际执行计划、查询结果与系统指标
- 必要的多次测试与实验条件控制
- 对异常现象、误差和实验局限的分析
- 能够支持结论的源码、文档或其他技术证据

不将理论预期冒充真实实验结果，不将单次性能测试结果泛化为普遍结论，也不把某一种数据库的特定实现当作所有数据库的通用机制。

文章在完成实验、结果分析和技术审稿之前，均视为研究草稿。

## 五、写作原则

本系列最重要的目标，是让复杂的数据库原理变得容易理解。

先建立直觉，再引入术语；先解释为什么需要某种机制，再说明它如何实现；先使用简单模型帮助理解，再逐步进入真实数据库内部。

避免堆砌专业术语，也不为了追求通俗而牺牲准确性。

希望具有基本 SQL 知识的读者能够逐步理解数据库内部机制，也希望有实际经验的开发者和 DBA 能从中获得更深入的技术认识。

**真正理解一个复杂系统，不是记住它包含多少组件，而是理解这些组件为什么存在，以及它们如何共同工作。**
